How it works

Three pieces of technology, explained in plain words.

Back to Scanner Resources How it was built

You take a photo of a page. A moment later you have a flat, clean, black-and-white scan, saved in a library on your device. Nothing is uploaded anywhere. Here is what happens in between.

1. Your photoChosen from your files or taken with the camera.
2. OpenCV.jsFinds the page, flattens it and cleans it up.
3. WebAssemblyMakes that work fast, in a background helper.
4. IndexedDBKeeps the photo and the scan in your library.

OpenCV.js: the eyes

OpenCV is a free toolbox for “computer vision”: teaching computers to make sense of pictures. It has been used for more than twenty years in robots, cars and phone cameras. OpenCV.js is the same toolbox, packaged so it can run inside a web browser.

Think of it as a very patient assistant with a ruler and a pair of scissors. For each photo it does this:

  1. Find the page. It turns the photo gray, smooths out the texture of the table, and looks for strong edges, the lines where something bright meets something dark. Then it looks for the biggest shape with four corners. That is almost always the page.
  2. Flatten it. A photo taken at an angle makes a rectangle look like a slanted, uneven shape. Knowing the four corners, OpenCV stretches the picture back into a straight rectangle, the way you would smooth a crumpled sheet onto a desk. This step is called a perspective warp.
  3. Clean it up. Shadows and uneven light make some parts of the page darker than others. First OpenCV estimates how bright the bare paper is in each area and evens that out. Then, instead of using one rule for the whole page, OpenCV decides “is this ink or paper?” for each small neighbourhood separately. This is called adaptive thresholding. The result is crisp black text on white paper, even where a shadow fell.

If it can't find four clear corners (for example, a white page on a white table), it uses the whole photo and tells you. A darker, plain background fixes that.

WebAssembly: the fast engine

OpenCV was written in C++, a programming language built for speed. Browsers normally run JavaScript, which is flexible but slower for heavy number-crunching like this.

WebAssembly (often shortened to Wasm) is a compact format that lets the browser run code like OpenCV's at nearly the speed of a normal desktop program. Think of it as shipping a pre-built engine instead of the blueprints: your browser downloads it once, keeps it, and runs it right on your device.

That engine is big (about 11 MB, or roughly 3.5 MB to download because it is compressed on the way). So the first visit shows “Loading the scanner…” for a moment. After that, your browser keeps a copy.

Why the page never freezes

Cleaning up a photo is heavy work. If the page did it directly, buttons would stop responding until it was done. So the scanner runs in a Web Worker: a helper that works in the background, like a kitchen that cooks while the waiter keeps talking to you. The page sends the photo to the helper, the helper sends back the finished scan, and you can scroll and tap the whole time. The progress bar shows each step as the helper finishes it.

Tidying up after itself

WebAssembly gives OpenCV its own block of memory. The browser's usual automatic clean-up can't see inside that block, so the scanner deletes every temporary picture it makes as soon as it is done with it. Our tests scan the same photos over and over and check that this memory doesn't grow.

IndexedDB: the filing cabinet

IndexedDB is a small database built into every modern browser. Websites can use it to save real files, such as photos, on your device. Each website gets its own private drawer that other websites can't open.

Every scan is saved there as two images (the original photo and the clean scan) plus a small preview, its name and the date. That's why your library is still there after you close the tab or restart the computer.

What this means for you

  • Private: your photos never leave your device. There is no server and no account.
  • Per browser: scans saved in one browser (or on one device) don't appear in another.
  • Yours to clear: clearing your browser's site data, or using Reset app data, deletes the library.

Updates and “Reset app data”

The database has a version number. When a new version of the app needs to change how scans are stored, it upgrades the database the first time you open it. If the app is also open in another tab with the older version, that tab is asked to step aside; if it can't, you'll see a message asking you to close the other tab.

If the app ever seems stuck, use Reset app data at the bottom of the scanner page. It deletes the saved scans on this device and starts fresh. For a deeper clean in Chrome: open DevTools (right-click → Inspect), go to Application → Storage, and under Clear site data click Clear selected. The guide shows every click.

Where it runs

The whole app is a handful of plain files (a page, a stylesheet, some JavaScript and the OpenCV engine) served by Netlify. Netlify only delivers the files; every bit of the actual work happens in your browser.
