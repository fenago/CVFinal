Meet the three technologies

Before you build, know what each piece does. OpenCV.js sees, WebAssembly makes it fast, IndexedDB remembers.

Your app runs entirely in the student's browser. Three pieces make that possible. Each one has one job.

The eyes

OpenCV.js

What it is: OpenCV, the world's most widely used computer vision library, packaged so it runs inside a web page. You load one file, opencv.js, and every OpenCV function is waiting for you on an object called cv.

What it does in your app: it looks at the photo and finds things. Edges (cv.Canny), shapes (cv.findContours), the four corners of a page (cv.approxPolyDP), then flattens and cleans it (cv.warpPerspective, cv.adaptiveThreshold).

The one rule: every image is a cv.Mat, and you must call .delete() on it when you are done. The browser will not clean it up for you.

const src = cv.imread(img);   // photo → cv.Mat
cv.cvtColor(src, gray, cv.COLOR_RGBA2GRAY);
cv.Canny(gray, edges, 75, 200);
cv.imshow('out', edges);
src.delete(); gray.delete(); edges.delete();
The engine

WebAssembly (Wasm)

What it is: a compact binary format that lets code written in languages like C++ run in the browser at close to native speed, inside the same security sandbox as JavaScript.

What it does in your app: OpenCV is written in C++. It was compiled to WebAssembly, and that is what is inside opencv.js. When you call cv.Canny, the work is done by fast Wasm code, not slow JavaScript.

Why it matters to you: Wasm has its own block of memory. That is why cv.Mat objects must be deleted, and why heavy work goes in a Web Worker (a background thread) so the page does not freeze while OpenCV thinks.

// main page
worker.postMessage({ type: 'scan', bitmap }, [bitmap]);
// worker: importScripts('opencv.js') → runs the pipeline
worker.onmessage = (e) => showResult(e.data);
The memory

IndexedDB

What it is: a database built into every browser. It stores large amounts of structured data, including files and images (Blobs), on the user's own computer. Each website gets its own private database.

What it does in your app: it keeps the scan library. Every scan is saved with its name and date, so it is still there after a refresh or a restart.

Key ideas: you open a database by name and version; the schema is created in onupgradeneeded; every read or write happens inside a transaction; everything is asynchronous so the page never waits.

const req = indexedDB.open('docscanner', 1);
req.onupgradeneeded = () =>
  req.result.createObjectStore('scans', { keyPath: 'id' });
// later: db.transaction('scans','readwrite')
//          .objectStore('scans').put(scan);
📷 Photo→Web Worker runs OpenCV.js on WebAssembly→Clean scan→Saved in IndexedDB

Good to know: nothing here needs a server or an API key. Netlify just serves the files; the student's browser does all the computer vision and keeps all the data. That is why this app deploys free and costs nothing to run.

When the app hangs: Inspect, IndexedDB, Clear site data

Browser apps like this sometimes get stuck: a busy worker, a blocked database upgrade, or old data. Here is exactly where to look in Chrome, and how to unstick it.

First, the easy fix: scroll to the bottom of the app and click Reset app data. It deletes the database and starts fresh.

If the page is frozen and you cannot click it, use Chrome DevTools:

  1. Right-click anywhere on the app and choose Inspect (or press ⌘ + Option + I on Mac, Ctrl + Shift + I on Windows).
  1. Click » (more tabs) at the top of DevTools, then Application. If you already see Application, click it directly.
  1. In the left sidebar, under Storage, find IndexedDB and click its arrow.
  1. Expand your database (here docscanner) and click it. You see its version and its object stores: scans, history and settings. To delete only this database, click Delete database.
  1. Click scans to see every saved scan, one row per scan. Click the arrow in the Value column to look inside a record.
  1. To reset everything: click Storage at the top of the sidebar. Under Clear site data, make sure IndexedDB is ticked, then click Clear selected. Close DevTools and reload the page.

Why it hangs, and the fix

What you seeLikely causeFix
Stuck on "Loading OpenCV…"opencv.js (about 10 MB) is still downloading, or failed to loadWait, then reload. Check the Console tab for a red error.
Stuck on "Working…"The Web Worker is busy or stuck on a very large photoThe app restarts the worker after 30 seconds. Or reload the page.
Stuck on "Opening library…"A blocked database upgrade: another tab of the app is still open on the old versionClose the other tabs of the app, then reload.
Errors or strange old dataOld or broken records in IndexedDBReset app data, or DevTools → Application → Storage → Clear selected.
Page gets slower after many scansA cv.Mat was not deleted (WebAssembly memory leak)Reload now; ask the orchestrator to have the WebAssembly expert find the leak.

Good to know: DevTools does not refresh IndexedDB live. Click the Refresh button above the table to see new scans. In these screenshots the address is localhost; yours will be your Netlify URL. The steps are identical.

Pick your own use case

The document scanner is the worked example. You may use it, but you will learn more with your own. Ideas that fit OpenCV.js + WebAssembly + IndexedDB on Netlify:

Coin counter

OpenCV.js: Hough circles find and size each coin. IndexedDB: a history of counts with the photo.

Face blur for privacy

OpenCV.js: Haar cascade face detection, then blur. IndexedDB: cache the cascade file and keep blurred photos.

Color palette extractor

OpenCV.js: k-means on pixels to find the main colors. IndexedDB: a saved palette library.

Webcam motion detector

OpenCV.js: frame differencing and contours on live video. IndexedDB: a log of motion events with snapshots.

Shape and object counter

OpenCV.js: thresholds and contours to count and measure parts or cells. IndexedDB: saved runs to compare.

Before / after photo enhancer

OpenCV.js: CLAHE, denoise and sharpen. IndexedDB: the before/after gallery.
